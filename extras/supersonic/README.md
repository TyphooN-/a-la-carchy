# Supersonic music widget

## Current canonical delivery — acceptance still required

The feature authority is the canonical Omarchy `shell/plugins/supersonic/`
source: metadata and basic playback, **no library popup, right-click search or
selected-track/album playback**. The older implementation documented below is
retained only as a legacy transport/layout baseline, not the default feature.

`native_delivery.py` accepts one exact, reviewed five-file canonical snapshot.
It copies the helper, request object and Service byte-for-byte; only the widget
module name and manifest identity/provenance are adapted to
`alacarchy.supersonic`. Native manifest fields are preserved, including the
playback description. `derivedFrom` is `omarchy.supersonic`; `clonedFrom` is not
set, so this never redirects the global MPRIS service. Source hashes are an
explicit version pin, not a recipe to accept arbitrary future source.

The packaged widget retains album `[current/total]` with unknown totals `?`,
quoted titles, year and timing labels, observed-state glyphs, hidden-unavailable
geometry and polling, timing generation protection, and fixed-player
`busctl --auto-start=no`. Removed operations remain refused by the canonical
helper. Do not copy the legacy popup back to obtain compatibility.

For a **private fixture**, explicitly supply the accepted canonical source:

```bash
python3 extras/supersonic/stage_plugin.py \
  --source /path/to/reviewed/omarchy/shell/plugins/supersonic \
  /path/to/private-review/alacarchy.supersonic
ALACARCHY_CANONICAL_SUPERSONIC_SOURCE=/path/to/reviewed/omarchy/shell/plugins/supersonic \
  python3 tests/supersonic-native-delivery.py
```

The configurator uses `ALACARCHY_SUPERSONIC_SOURCE` when explicitly provided,
otherwise the selected Omarchy tree's `shell/plugins/supersonic`. Missing or
unreviewed canonical source fails closed; it never falls back to the older
media popup. Checking or re-enabling an already hash-owned canonical plugin
does not require the original source directory to remain present. A legacy
plugin cannot satisfy the canonical enabled check and is **not** silently reused
or overwritten; its guarded migration remains an installation step after
independent acceptance. Disable continues to preserve staged files and restore
the saved media layout entry.

Ownership is checked against the independently pinned generated bytes and full
file set, not hashes asserted only by the editable target manifest. Admission
refuses unexpected entries, unsafe types/links and changed source. Creation is
hidden until complete and uses Linux atomic no-replace publication. It does not
promise atomic ancestor protection against a hostile non-cooperating same-user
writer; installation still requires exact preimages and sole ownership.

All preview/test commands remain offline. Synthetic/native offscreen proof is
not independent source acceptance, guarded live installation or visual QA.

## Legacy baseline (not the canonical feature authority)

A native Omarchy bar widget for **Supersonic 0.22.1** using the app's local UNIX HTTP IPC. It does not read server configurations, passwords, credential stores or artwork URLs; it does not install, launch, restart or stop Supersonic.

## Enable / disable (after acceptance)

Run `bash a-la-carchy.sh` from the **full checkout**, then choose **Appearance → Supersonic music → Enable**. Python 3 and the installed Omarchy native media primitives are required. This optional integration is not bundled into the single-file/curl one-liner; missing checkout helpers produce a failure, not a partial download or a success claim.

Enable stages `~/.config/omarchy/plugins/alacarchy.supersonic/` and replaces a single stock `omarchy.media` layout entry in place, retaining its settings and a marked original ID. If there is no stock media entry, it appends the widget to the center without removing custom media widgets. Multiple stock entries, malformed layouts, symlink configs, unfamiliar existing plugins and changed managed source files are refused. The shared configurator confirmation/backup/read-back flow applies. No package-owned files are edited.

**Disable** restores the original native media ID (retaining later per-entry setting edits), or removes the entry added by Enable. It leaves staged plugin files and unrelated bar/settings data intact. Enable and Disable are idempotent. No service restart is used; saving user plugin/layout files can hot-reload the shell, so enable is a live activation step reserved for acceptance. The stock MPRIS service and global media shortcuts are not redirected to this widget.

Existing managed plugins are reused, never overwritten. To upgrade after editing or when a new implementation is desired: disable first, preserve/rename the old plugin directory, then enable to stage a fresh directory. If configuration writing fails after staging, the inactive plugin directory may remain; the configurator reports failure and preserves its config backup.

## Display and controls

- Horizontal bar: artist · track · album · year · **elapsed / total**, using full natural width up to 1000 native theme units (rather than the original 280-unit cap). Inline `maxLabelWidth` can adjust the cap (120–1600); narrow screens additionally cap it to 60% of the bar width. Full metadata and click hints are available in the tooltip. Vertical bars show a media glyph with the same popup/tooltip.
- Elapsed/total comes from one typed, read-only D-Bus `GetAll` snapshot of the exact `org.mpris.MediaPlayer2.Supersonic` player, matched to the IPC track via the versioned UTF-8/base32 `mpris:trackid` contract. `busctl` (provided by systemd on Omarchy) is required for timing. This avoids Qt's opaque `QDBusObjectPath` metadata conversion. Samples refresh every second while a track is present, without overlapping timing calls, with a two-second deadline and 512 KiB reply cap. Display is `m:ss` or `h:mm:ss`; absent/mismatched/invalid timing is `--:--`, never another player's or old track's duration. The glyph follows observed playing/paused state when available.
- **Closed/unavailable app:** the widget is completely hidden, including its glyph, text and layout space. Starting Supersonic restores it automatically on the next successful background status poll (normally within three seconds); an open popup closes when the app disappears. An available but idle app remains visible so its library can still be searched.
- **Left-click:** play/pause. **Middle-click:** next. **Right-click:** open/close the native popup while Supersonic is available. **Scroll up/down:** previous/next. Supersonic's previous action may first seek back within the current track (the app's own behavior).
- Popup: track, artist, album/year, previous/play-pause/next buttons and one **Search music…** field. **All** is the default; Songs/Albums are optional filters, not required search modes. Mixed rows are labeled Song/Album and retain their actual type/ID for playback.
- Search: 2–256 characters, 300ms debounce; Enter searches immediately. All queries the native song and album endpoints concurrently with two bounded readers, interleaves both kinds and deduplicates within kind/ID, then caps the combined view at 40. Album matches cannot be hidden behind a long song list. Truncation and partial endpoint failures are explicitly labeled; failed calls cannot silently imply a complete search.
- Matching is delegated to the already-configured Supersonic library, not a filter over currently visible/cached rows. Supersonic 0.22.1's Subsonic track iterator expands song, album and artist matches into tracks; live title, album and band-name probes have exercised that behavior. The IPC has no separate artist-results endpoint and no guaranteed regex mode. No local regex over a partial result set is presented as library-wide regex search.
- Click or focus a result and press Enter/Space to request actual track-ID or album-ID playback. Albums start at index 0, shuffle off. Query/filter changes immediately clear results and reject obsolete completions/selections.
- Tab focuses controls/results; Enter on the bar opens the popup; Space toggles playback; Escape in the popup closes it. Live focus and outside-click dismissal still require compositor acceptance testing.

## Honest metadata and failures

The 0.22.1 `/current_track` response is `MediaItemMetadata` with `Name`, `Artists`, `Album` and `ID`, **not** `Track.Title`/`ArtistNames`, and it contains **no Year or playing/paused flag**. The helper returns the current track metadata; once per newly observed track, the widget searches IPC `/transport/search-track?s=...` using its title and reads `Track.Year` only for a unique **exact ID match within the first 40 results**. Missing/zero/ambiguous/truncated/unavailable year matches show **Year unknown**. Album search uses `Album.Date.Year`. No inferred dates, guessed album years, or server credential scraping.

The playing/paused glyph comes from matching Supersonic MPRIS data; without that data it remains neutral. IPC current-track metadata alone does not prove playback is active. In upstream 0.22.1, play-track/play-album handlers discard backend playback errors and acknowledge the request; the widget therefore labels the command as **Playback requested**, never “now playing” solely from a command receipt. Track metadata refreshes after actions and every three seconds; elapsed/total refreshes every second from MPRIS.

Unavailable app/socket, empty queue, timeout, refused socket, unsupported/malformed response, oversized search, no matches and command failure are distinct states. Failures clear current metadata rather than leaving a stale song displayed. Raw IPC error strings, server names, query text and song metadata are not sent to shell diagnostics. Search is still a request through the already-configured app to its library and can fail when that app is disconnected.

## Transport boundaries

- Only `$XDG_RUNTIME_DIR/supersonic.sock`; no TCP, proxy, `/tmp` fallback, environment dump, server config or credentials.
- Runtime directory must be absolute, a real same-user directory and not group/world writable. Socket must be a non-symlink same-user UNIX socket. Linux `SO_PEERCRED` checks the connected peer UID, protecting against pre-connect path replacement.
- Fixed allowlisted operations; query strings and IDs URL-encoded. Private arguments are JSON on stdin, never interpolated into a shell or command argv.
- Two-second total connect/read deadline (including slow/dribbling responses), 512 KiB response cap, 8 KiB input cap, 40 displayed/scanned results, capped metadata fields. A 3.5-second QML watchdog kills only its own helper if launch/termination fails.
- IPC search in this app version has no pagination/result-limit parameter: a broad search can cause the app itself to enumerate many results even though the helper caps memory/time/display. Narrow the query; oversized replies are rejected with a visible message rather than silently accepted.
